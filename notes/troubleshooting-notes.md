# Troubleshooting Notes

## Issue 1 — Event IDs Not Returned by Initial PowerShell Query

### Cause

The initial PowerShell query searched only the most recent 30 System events, which did not include the restart events.

### Resolution

Increase the search range or use a more targeted query with `FilterHashtable` to retrieve specific Event IDs.

---

## Issue 2 — Expected Restart Event IDs Missing

### Cause

The expected restart Event IDs (`1074`, `6005`, `6006`, `6008`, `41`, `12`, `13`) were not generated on the Windows 11 system after a normal restart.

### Resolution

Review the latest System events using Event Viewer and PowerShell to determine which restart-related events are actually generated by the operating system before investigating Wazuh collection.

---

## Issue 3 — No Restart Events Found in Wazuh Discover

### Cause

Since Windows did not generate the expected restart Event IDs, Wazuh had no corresponding events to ingest.

### Resolution

Always verify event generation in Windows Event Viewer before assuming a Wazuh ingestion or indexing issue.

---

## Issue 4 — PowerShell Query Returned No Results

### Cause

The PowerShell query filtered for Event IDs that were not present in the available System log history.

### Resolution

Enumerate recent System events first, then build queries using the Event IDs that actually exist on the endpoint.

---

## Issue 5 — Event Viewer and PowerShell Produced Different Results

### Cause

Event Viewer allows broader manual inspection, while PowerShell returns only events that match the specified filters.

### Resolution

Use Event Viewer to identify available events, then refine PowerShell queries for precise validation.

---

## Issue 6 — Verify Wazuh Agent Health

### Cause

Whenever expected events are absent from Discover, the Wazuh agent should be verified before investigating further.

### Resolution

Confirm the Windows agent is connected and actively communicating with the manager.

```bash
sudo /var/ossec/bin/agent_control -i 001
```

Expected output:

- Agent Status: **Active**
- Latest Keep Alive updated
- Windows endpoint successfully connected

---

# Lessons Learned

- Always verify Windows event generation before troubleshooting Wazuh.
- Windows restart-related Event IDs can differ across Windows versions and builds.
- Event Viewer should be treated as the authoritative source during Windows DFIR investigations.
- PowerShell provides fast validation but depends entirely on accurate filtering.
- Wazuh can only ingest events that Windows actually generates.
- Structured validation of the endpoint before the SIEM prevents unnecessary troubleshooting and leads to more accurate forensic conclusions.
